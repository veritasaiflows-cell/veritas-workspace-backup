# 1-Week Sprint Structure

> Archived note. This file belongs to a retired operating branch. Preserve it as historical context, not current doctrine. Current live identity and operating rules are defined by SOUL.md, IDENTITY.md, AGENTS.md, MEMORY.md, and FINANCE_SOUL.MD.

## Working title

AI Opportunity Operating System Setup Sprint

## Goal

In one week, help the client move from scattered ideas and opportunity overload into a structured operating system with clearer priorities and a repeatable decision rhythm.

## Day 1 - Intake and diagnosis

- understand the client's current opportunity overload
- identify goals, bottlenecks, and failure patterns
- inventory active ideas, projects, and directions
- identify where attention is being wasted

## Day 2 - Structure and scoring

- create the opportunity categories
- create or customize the scoring rubric
- define statuses and pipeline structure
- define what makes something active, paused, or killed

## Day 3 - Dashboard and review system

- build the dashboard
- define the weekly review structure
- define the one-project-at-a-time rule if appropriate
- define what the client should look at daily and weekly

## Day 4 - Opportunity ranking and pruning

- score current opportunities
- rank them
- identify weak, distracting, or low-quality items
- choose the primary focus

## Day 5 - Handoff and execution plan

- deliver the full operating system
- explain how to use it
- define next actions
- define the first execution week after the sprint

## Final deliverables

- customized opportunity pipeline
- customized scoring rubric
- dashboard structure
- weekly review system
- ranked current opportunities
- first next-action plan
- written explanation of how to operate the system
