## Global Authority Rules

- Active Workflows owns live queue state; continuity notes own resume detail; `tmp/` owns proof/review packets; the alerts-and-recommendations canon plus guarded SQL own finance/alert truth.
- No generated artifact, dashboard, Today card, packet, SQL row, score, or validator implies owner approval or execution authority.
- `tmp/pm-value-added-register.json` is informational only and must not be used as execution or readiness gate.
- Veritas main remains final integrator and truth owner; helper lanes support but do not publish final authority.
- Parallel helpers should implement bounded slices only after a clean lane-register preflight and exact write leases. Do not re-open completed QA/audit lanes as default work; refresh candidate lanes after material state changes and use PM-derived candidates to pick implementation-first slices.
- Heartbeat packets are handoff/prep signals only. Heartbeat must use only `python scripts\heartbeat_priority_handoff.py --write --validate`, which writes heartbeat-only receipt artifacts and routes P0/P1 review to Main. It must not invoke the escalation consumer or action executor directly, execute proof commands, spawn helpers, or mutate authority surfaces. PM packets can be picked up by `main_session_action_executor.py` only from main/cron/closeout contexts.
- If proof is stale, partial, missing, or contradictory, downgrade confidence and inspect owner artifacts before claiming readiness.
- Archive/cleanup recommendations are review-only until reference checks, hash manifest, destination plan, and explicit owner approval.
- Standing finance maintenance is limited to alert policy, thesis context, evidence, source lineage, routing, freshness, bands, and invalidation thresholds through exact approved gates. Portfolio construction/state maintenance is retired.
- Paper/live execution and simulated account-state maintenance are outside the active OS. WF63/WF67 are deny-only historical safety surfaces.
