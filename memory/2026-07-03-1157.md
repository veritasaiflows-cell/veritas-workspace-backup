## Key findings

### 1. Two different isolation models exist

| Type | Lives at | Use case | Isolation level |
|---|---|---|---|
| **Multi-agent isolated agents** | `~/.openclaw/agents/<agentId>/` | Persistent personas/people | Full: own workspace, auth, sessions, model config |
| **Sub-agents (sessions_spawn)** | runtime sessions like `agent:<id>:subagent:<uuid>` | Background/parallel tasks | Session-only; inherits agent workspace + auth; optional fork |

What you are calling "isolated agents" probably means **multi-agent isolated agents** via `agents.list[]`, not sub-agents. Sub-agents are transient background workers.

### 2. Workspace path is configurable, not a fixed `workspaces` folder

- Default: `~/.openclaw/workspace`
- Profile variant: `~/.openclaw/workspace-<profile>`
- Per-agent: `agents.list[].workspace`
- Sandbox variant: `~/.openclaw/sandboxes/...`

So `C:\Users\Veritas\.openclaw\workspaces` is **not a standard OpenClaw path**. If you created it, it is custom. If you are planning to, you should know it is not automatically recognized.

### 3. Each isolated agent gets its own `agentDir`

Important paths:

- Config: `~/.openclaw/openclaw.json`
- State dir: `~/.openclaw`
- Agent dir: `~/.openclaw/agents/<agentId>/agent`
- Sessions: `~/.openclaw/agents/<agentId>/sessions`
- Workspace: whatever you set per agent

This means auth profiles, model registry, and session history are fully isolated between agents.

### 4. Auth is per-agent but falls back to main

Each agent loads:
- its own `~/.openclaw/agents/<agentId>/agent/auth-profiles.json`
- main agent profiles as fallback

OAuth refresh tokens are **not cloned** to secondary agents. If you want independent OAuth accounts, you must sign in from that agent.

### 5. Workspace is default cwd, not a hard sandbox

Critical warning from the docs:

> The workspace is the **default cwd**, not a hard sandbox. Tools resolve relative paths against the workspace, but absolute paths can still reach elsewhere on the host unless sandboxing is enabled.

So isolated agents are **not filesystem-sandboxed by default**. For real isolation, enable `agents.defaults.sandbox` or per-agent sandbox.

### 6. Sub-agents do NOT get full bootstrap files

By default, sub-agents only inject `AGENTS.md` and `TOOLS.md`. They do NOT get:
- `SOUL.md`
- `IDENTITY.md`
- `USER.md`
- `MEMORY.md`
- `HEARTBEAT.md`
- `BOOTSTRAP.md`

This is a built-in safety boundary. If you want isolated agents to have a richer persona, they must be configured as separate `agents.list[]` entries, not spawned as sub-agents.

### 7. Skills are scoped per workspace

Workspace `skills/` has highest precedence for that workspace. But skill allowlists can be configured per-agent via `agents.list[].skills`. This means each isolated agent can have a different skill surface.
