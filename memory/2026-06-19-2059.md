### Part 1: Audio — Three Paths, Zero to Low Cost

#### Path A: TTS (Outbound Voice Replies) — Free, 5 Minutes

Enable **Microsoft TTS** — no API key, uses Edge's public neural TTS:

```json5
{
  messages: {
    tts: {
      auto: "always",          // or "tagged" to only speak when you ask
      provider: "microsoft",
      providers: {
        microsoft: {
          speakerVoice: "en-US-MichelleNeural",
          lang: "en-US",
          outputFormat: "audio-24khz-48kbitrate-mono-mp3",
        },
      },
    },
  },
}
```

Then in chat: `/tts on` → every reply gets an audio attachment. `/tts chat on` for current session only. `/tts audio <text>` for one-off.

**Better quality options (need API key):**
- **OpenAI** (`gpt-4o-mini-tts`, voices: alloy/echo/fable/onyx/nova/shimmer/coral/cedar) — most natural, `$OPENAI_API_KEY`
- **ElevenLabs** — best voice quality/cloning, `$ELEVENLABS_API_KEY`

#### Path B: Talk Mode (Realtime Voice Conversation) — Needs API Key

Browser-based realtime voice through Control UI. You talk, Veritas talks back — no typing.

Requires one of:
- **OpenAI Realtime** — WebRTC, `OPENAI_API_KEY`, configure `talk.realtime.provider: "openai"`
- **Google Live** — WebSocket, `GEMINI_API_KEY`, configure `talk.realtime.provider: "google"`

Then in Control UI chat: click the waves button next to the mic icon. Browser handles microphone, Gateway handles credentials.

#### Path C: Voice Note Workflow (Already Working, Just Use It)

Current flow: Telegram voice note → `media\inbound` → `local_audio_transcriber.py` → transcript → Veritas responds in text.

To close the loop with voice replies: enable TTS (Path A), then inbound voice gets a spoken response back.

### The Fastest Win: Microsoft TTS

No API key. No cost. Five minutes of config. Every Veritas reply gets a spoken audio attachment in WebChat. Combine with Telegram voice notes and you have a full voice-in/voice-out loop.

Want me to walk through the exact config change for TTS, or test the existing audio transcriber on one of those 30+ inbound voice notes?
assistant: **Plan: Veritas Audio + Better UI**

Blunt recommendation: start with the **lowest-risk audio loop first**, then add realtime voice only after transcripts, controls, and finance stop-lines are solid.

**Phase 1 — Immediate Voice Loop**
Goal: voice-in / voice-out without touching decision authority.

1. Enable **Microsoft TTS** in OpenClaw config.
2. Keep mode as `tagged` first, not `always`.
3. Test:
   - `/tts audio Hello from Veritas`
   - one Telegram voice note
   - one WebChat response with TTS
4. Run `scripts/local_audio_transcriber.py --write --pretty --validate` on the newest inbound `.ogg`.

Decision: if TTS quality is acceptable, keep Microsoft for free baseline. If it feels robotic, evaluate OpenAI `gpt-4o-mini-tts` next.

**Phase 2 — Audio Inbox**
Goal: make voice notes useful, searchable, and safe.

Build or wire a small “Audio Inbox” panel in Control UI:

| Field | Purpose |
|---|---|
| Audio file | Play original voice note |
| Transcript | Editable before sending to Veritas |
| Source | Telegram / WebChat / file |
| Intent tag | finance, workflow, note, task, personal |
| Confidence | transcription quality |
| Send button | only sends approved transcript |

Rule: **audio becomes text before action**. No finance workflow should run directly from raw speech.

**Phase 3 — Spoken Veritas Replies**
Goal: reduce reading load without making every reply noisy.

Use TTS policy:

| Mode | Use |
|---|---|
| `tagged` | Default. Veritas speaks only when requested. |
| `summary-only` | Ideal future mode: speak the conclusion, leave proof in text. |
| `always` | Only for casual/non-finance sessions. |

For finance responses, spoken reply should be short:
- verdict
- key risk
- next action
- “details are in the text”

Do **not** read long ticker reports aloud by default.

**Phase 4 — Realtime Talk Mode**
Goal: natural conversation, but only for low-risk workflows first.

Enable OpenAI Realtime or Google Live only after Phase 1-3 work.

Allowed realtime use:
- status checks
- brainstorming
- daily planning
- summarizing notes
- capturing tasks
- explaining dashboards

Blocked realtime use:
- paper/live order approval
- portfolio/canon mutation
- config/auth/runtime changes
- final finance recommendations without transcript review

Realtime voice should produce a transcript artifact every time.

**Phase 5 — Better UI/UX**
Build the Control UI around Randall’s real workflows, not generic chat.

Recommended layout:

| Area | Function |
|---|---|
| Main chat | Conversation with Veritas |
| Audio rail | voice notes, transcripts, TTS controls |
| Finance card rail | ticker, band, stop, state, authority |
| Proof drawer | sources, local artifacts, validators |
| Action queue | next safe action, blockers, approval needed |
| Mode selector | Ask / Research / Finance / Workflow / Audio Inbox |
