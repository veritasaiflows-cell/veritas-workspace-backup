3. The implementation contract stops at “next action,” not “resume cursor.”

- `last_completed_step`
- `in_progress_step`

- checkpoint sequence/id
- proof hashes bound to the completed step
- resume acknowledgement

4. There is no explicit precedence rule.

`active leased lane > exact workflow checkpoint > named workflow continuity note > PM queue > general status`

5. The recovery packet is too noisy.

The future-session packet contains many unrelated warnings and stale-input notices. The active action is not strongly separated from global maintenance debt, so the next instance spends effort triaging the packet instead of resuming.

6. Historical and active lane state are mixed.

The lane register is approximately 6 MB and contains more than 1,500 historical lanes. A new instance should never need to parse that history to find one active lane.
