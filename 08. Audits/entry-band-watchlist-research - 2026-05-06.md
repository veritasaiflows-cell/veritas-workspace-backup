# Research: Best Way to Update Entry Bands on a Stock Watchlist

## Executive Summary

For the Veritas / OpenClaw watchlist, the best entry-band update policy is:

> **Keltner-first, Dual-MA-gated, SMA-envelope-audited.**

This means:

- **Use Keltner Channel as the default entry-band generator** because it adapts to each stock's realized volatility through ATR.
- **Use Dual Moving Average Band as the trend and reclaim gate** because the 20/50/200 moving-average stack is better at determining whether a stock is tradable, extended, broken, or reclaim-only.
- **Use SMA Envelope as a secondary audit or fallback**, not as the primary method, because a fixed-percentage envelope is too rigid across different types of stocks.

This fits the watchlist model shown in the screenshot, where names can be labeled as:

- `IN BAND`
- `NEAR BAND`
- `BELOW STOP`
- `MID-BAND`
- `Vault band`
- `EARNINGS IMMINENT`

The key design principle is that the entry band should be generated by a rules engine, not by manual guessing.

## Recommended Operating Model

The best default logic is:

```text
Primary method: Keltner Channel
Required gate: Dual MA / 20-50-200 trend stack
Audit method: SMA Envelope
Special mode: Vault band for broken charts
Special mode: Earnings freeze around imminent reports
```

Recommended dashboard language:

```text
Entry band is volatility-adjusted by Keltner Channel and validated by MA stack.
SMA Envelope is shown only as an audit/reference band.
Below-stop names receive reclaim-only Vault bands, not automatic dip-buy bands.
```

## Why Keltner Channel Should Be the Primary Band Engine

A Keltner Channel is usually built from:

```text
Centerline = EMA
Upper band = EMA + ATR multiplier
Lower band = EMA - ATR multiplier
```

A common implementation uses a 20-period EMA and an ATR multiplier such as 2.0.

The advantage is that the band width adapts to volatility. This matters because a mixed stock watchlist can include very different volatility profiles:

- Defense stocks such as LMT or RTX
- Banks such as JPM or GS
- Megacap technology such as MSFT
- High-beta growth or semiconductor names such as NVDA
- Energy or commodity-sensitive names such as LNG

A fixed 3%, 5%, or 8% SMA envelope will often be too tight for one stock and too loose for another. A Keltner Channel naturally expands and contracts with each ticker's realized behavior.

Core rule:

```text
Keltner defines the actionable price zone.
Dual MA defines whether that zone is valid.
```

## Method Comparison

| Method | Best Use | Strength | Weakness | Recommended Role |
|---|---|---|---|---|
| **Keltner Channel** | Volatility-adjusted entry zone | Adapts to each stock's ATR; avoids one-size-fits-all bands | Can invite bad dip-buying in a downtrend if not filtered | **Primary band engine** |
| **Dual MA Band** | Trend state, reclaim state, support cluster | Easy to explain; aligns with 20/50/200 stack logic | Lagging; does not directly know volatility | **Gate and confidence filter** |
| **SMA Envelope** | Simple audit band | Stable, transparent, easy to display | Fixed percentage is fragile across tickers and regimes | **Secondary sanity check only** |
| **Bollinger Band** | Optional volatility diagnostic | Shows standard-deviation expansion/compression | Can widen after volatility spikes and become less useful for clean entries | Optional, not core |

## Recommended Band Selection Logic

For every ticker, calculate all three methods:

```text
EMA20
EMA50
SMA200
ATR20
ATRP20 = ATR20 / close
Keltner mid = EMA20
Keltner lower = EMA20 - multiplier * ATR20
Keltner upper = EMA20 + multiplier * ATR20
SMA envelope = SMA50 or SMA100 +/- fixed percent
Dual MA band = relevant 20/50/200 MA cluster
```

Then select the displayed operating band based on trend state.

| Stock State | Displayed Band |
|---|---|
| Bullish stack: price > EMA20 > EMA50 > SMA200 | Keltner pullback band |
| Constructive but not fully stacked | Keltner band constrained by EMA50 |
| Above all MAs but extended | Wait-for-pullback band, not chase band |
| Below 20/50 but above 200 | Reclaim band around EMA50 / Keltner mid |
| Below 200 or below all MAs | Vault / reclaim-only band |
| Earnings imminent | Freeze or mark event-risk band |
| Post-earnings | Recalculate after new range forms |

This avoids the most dangerous failure mode: continuously lowering the entry band on a broken chart until a failed setup appears attractive only because it has fallen.

## Default Keltner Entry-Band Formula

Use daily data for the operating band. Weekly or monthly data can remain as context in the chart, but daily data should drive the actionable watchlist band.

```text
close = latest adjusted close
EMA20 = 20-day exponential moving average
EMA50 = 50-day exponential moving average
SMA200 = 200-day simple moving average
ATR20 = 20-day average true range
ATRP20 = ATR20 / close
```

Set the ATR multiplier by volatility bucket:

```text
if ATRP20 < 1.5%:
    multiplier = 1.5

if ATRP20 >= 1.5% and ATRP20 <= 3.5%:
    multiplier = 2.0

if ATRP20 > 3.5%:
    multiplier = 2.5
```

Then calculate:

```text
KC_mid  = EMA20
KC_low  = EMA20 - multiplier * ATR20
KC_high = EMA20 + multiplier * ATR20
```

For a clean bullish stack:

```text
Keltner zone = [KC_low, KC_mid + 0.25 * ATR20]
MA zone      = [EMA50 - 0.50 * ATR20, EMA20 + 0.25 * ATR20]

Entry band = intersection of Keltner zone and MA zone
```

If the intersection is too narrow, use a blended fallback:

```text
Entry low  = max(KC_low, EMA50 - 0.50 * ATR20)
Entry high = EMA20 + 0.25 * ATR20
```

This gives the watchlist a band that is both volatility-aware and trend-aware.

## Vault Band / Reclaim-Only Logic

The screenshot shows names such as LMT and RTX labeled as `BELOW STOP`, with a `Vault band` above the current price. That is the correct concept.

For names below key moving averages, do not keep moving the normal entry band downward. Instead, switch the name into a reclaim-only state.

```text
status = BELOW STOP or RECLAIM ONLY
band_type = Vault / Reclaim
reclaim_low = max(EMA50, SMA200, recent 20-day breakdown/reclaim level)
reclaim_high = reclaim_low + 1.0 to 1.5 * ATR20
stop = reclaim_low - 1.0 to 1.25 * ATR20
```

Dashboard interpretation:

```text
Vault band = price must reclaim this area before it becomes deployable again.
```

This prevents the system from treating every falling stock as automatically more attractive.

---

## Stop / Invalidation Logic

Every entry band should include a stop or invalidation level.

For bullish pullback bands:

```text
stop = min(
  entry_low - 1.25 * ATR20,
  recent 63-day swing low - 0.25 * ATR20
)
```

For reclaim-only bands:

```text
stop = reclaim_low - 1.0 * ATR20
```

In the user interface, label this as:

```text
Technical invalidation
```

Do not imply guaranteed execution. Stop orders may execute at prices different from the stop price during volatility or gaps, and stop-limit orders may fail to execute.

## Band Status Labels

Recommended status logic:

```text
if close >= entry_low and close <= entry_high:
    band_status = IN BAND

elif close > entry_high and close <= entry_high * 1.03:
    band_status = NEAR BAND

elif close < stop:
    band_status = BELOW STOP

elif trend_state == BROKEN:
    band_status = RECLAIM ONLY

elif close > entry_high * 1.03:
    band_status = ABOVE BAND / WAIT

else:
    band_status = WATCH
```

For high-beta names, the `NEAR BAND` threshold can be widened from 3% to 5%. For low-volatility names, keep it closer to 2% to 3%.

## Update Cadence

| Coverage Lane | Refresh Cadence | Write-Back Policy |
|---|---|---|
| Execution lane | Daily after close | Auto-calculate, human-gated publish |
| Watch lane | Weekly or event-driven | Auto-calculate, manual promotion |
| Macro/context lane | Weekly/monthly | Display only |
| Speculative lane | Event-driven | No automatic deployment band |

The band engine should update the derived operating surface, but should not mutate canonical notes without human review.

Recommended update triggers:

```text
Update band if:
- Price enters band
- Price exits band by more than 2%
- ATRP changes by more than 25% from prior band calculation
- EMA20/EMA50/SMA200 stack changes state
- Earnings window opens or closes
- Post-earnings range is established
- Split/corporate action is detected
```

To reduce dashboard churn:

```text
If the new band differs by less than 1%, keep the prior displayed band and mark it as stable.
```

## Earnings Rule

Because the screenshot includes `EARNINGS IMMINENT`, the entry-band engine should have a special earnings mode.

Recommended logic:

```text
T-minus 7 trading days:
  freeze normal deployment band
  mark event risk
  allow only starter-size / watch status

T+1 to T+3 after earnings:
  recalculate ATR and moving averages
  but do not immediately promote unless price confirms range

After post-earnings range forms:
  resume normal Keltner-first band selection
```

This avoids false precision before a binary gap event.

## Macro Regime Filter

The screenshot includes a macro regime filter with states such as:

- Low Rate / Low Vol
- Tightening Cycle
- Vol Spike / Crisis
- Easing / Recovery
- Peak Rate Hold
- Stimulus / Capex Boom

The entry-band engine should not use macro regime as the primary band calculator. It should use macro regime to modify confidence, multiplier, and position-size guidance.

Suggested adjustments:

| Macro Regime | Band Adjustment |
|---|---|
| Low Rate / Low Vol | Normal Keltner multiplier |
| Tightening Cycle | Require stronger MA confirmation |
| Vol Spike / Crisis | Widen band, reduce confidence, require reclaim |
| Easing / Recovery | Allow constructive reclaim setups |
| Peak Rate Hold | Keep normal band but require sector confirmation |
| Stimulus / Capex Boom | Allow trend-continuation setups if MA stack is bullish |

Example:

```text
if regime == "Vol Spike / Crisis":
    multiplier += 0.5
    confidence -= 1
    require_price_above_EMA50 = true
```

## Backtest Framework Before Production

Do not optimize each ticker separately. That creates overfitting risk.

Backtest the band engine by ticker class, not ticker-by-ticker:

```text
Class 1: Low-volatility compounders
Class 2: High-beta growth / semiconductors
Class 3: Banks / cyclicals
Class 4: Defense / industrials
Class 5: Energy / commodity-sensitive
```

Measure:

```text
1. First-touch bounce rate
2. 20-day, 60-day, and 120-day forward return after band touch
3. Max adverse excursion after entry
4. Stop-out rate
5. Time spent in band
6. False reclaim rate
7. Earnings-window failure rate
8. Missed-entry rate when price never returns to band
```

The goal is not to find the perfect parameter for every stock. The goal is to find a robust default policy that works reasonably across stock classes and does not collapse out of sample.

## Suggested Implementation Pseudocode

```python
def classify_trend(close, ema20, ema50, sma200):
    if close > ema20 > ema50 > sma200:
        return "BULLISH_20_50_200"
    if close > ema20 and close > ema50 and close > sma200:
        return "ABOVE_ALL_MAS"
    if close > sma200 and (close < ema20 or close < ema50):
        return "ABOVE_200_BELOW_20_50"
    if close < sma200 and close < ema20 and close < ema50:
        return "BELOW_ALL_MAS"
    if close < sma200:
        return "BELOW_200"
    return "MIXED"


def select_atr_multiplier(atrp20):
    if atrp20 < 0.015:
        return 1.5
    if atrp20 <= 0.035:
        return 2.0
    return 2.5


def calculate_entry_band(close, ema20, ema50, sma200, atr20, atrp20, earnings_state=None):
    trend = classify_trend(close, ema20, ema50, sma200)
    multiplier = select_atr_multiplier(atrp20)

    kc_mid = ema20
    kc_low = ema20 - multiplier * atr20
    kc_high = ema20 + multiplier * atr20

    if earnings_state == "IMMINENT":
        return {
            "method": "EARNINGS_FROZEN",
            "type": "EVENT_RISK",
            "low": kc_low,
            "high": kc_high,
            "status": "EARNINGS_IMMINENT",
            "trend": trend,
        }

    if trend in ["BELOW_200", "BELOW_ALL_MAS"]:
        reclaim_low = max(ema50, sma200)
        reclaim_high = reclaim_low + 1.25 * atr20
        stop = reclaim_low - 1.0 * atr20
        return {
            "method": "DUAL_MA_RECLAIM",
            "type": "VAULT_RECLAIM",
            "low": reclaim_low,
            "high": reclaim_high,
            "stop": stop,
            "status": "RECLAIM_ONLY",
            "trend": trend,
        }

    if trend == "BULLISH_20_50_200":
        entry_low = max(kc_low, ema50 - 0.50 * atr20)
        entry_high = ema20 + 0.25 * atr20
        stop = min(entry_low - 1.25 * atr20, ema50 - 1.5 * atr20)
        return {
            "method": "KELTNER_MA_CONSTRAINED",
            "type": "PULLBACK",
            "low": entry_low,
            "high": entry_high,
            "stop": stop,
            "status": classify_band_status(close, entry_low, entry_high, stop),
            "trend": trend,
        }

    entry_low = kc_low
    entry_high = kc_mid + 0.25 * atr20
    stop = entry_low - 1.25 * atr20
    return {
        "method": "KELTNER_PRIMARY",
        "type": "WATCH",
        "low": entry_low,
        "high": entry_high,
        "stop": stop,
        "status": classify_band_status(close, entry_low, entry_high, stop),
        "trend": trend,
    }


def classify_band_status(close, entry_low, entry_high, stop):
    if close < stop:
        return "BELOW_STOP"
    if entry_low <= close <= entry_high:
        return "IN_BAND"
    if close > entry_high and close <= entry_high * 1.03:
        return "NEAR_BAND"
    if close > entry_high * 1.03:
        return "ABOVE_BAND_WAIT"
    return "WATCH"
```

## Final Recommendation

Use this production policy:

```text
1. Calculate Keltner, Dual MA, and SMA Envelope for every ticker.
2. Use Keltner as the default entry-band generator.
3. Use Dual MA to decide whether the band is valid, reclaim-only, or broken.
4. Use SMA Envelope only as an audit/reference overlay.
5. Freeze or mark bands around imminent earnings.
6. Convert broken charts into Vault / Reclaim bands instead of lowering dip-buy bands.
7. Refresh daily after close for active names and weekly for watch-only names.
8. Require human-gated publish for deployment-relevant band changes.
```

This approach is more robust than using any single method alone. It is volatility-aware, trend-aware, less prone to false dip-buy signals, and better suited to a mixed stock watchlist.
