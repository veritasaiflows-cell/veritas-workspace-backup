# Pilot Client Rules

> Archived note. This file belongs to a retired operating branch. Preserve it as historical context, not current doctrine. Current live identity and operating rules are defined by SOUL.md, IDENTITY.md, AGENTS.md, MEMORY.md, and FINANCE_SOUL.MD.

## Purpose

Protect the quality of the first pilots and avoid wasting time on poor-fit free work.

## Rules

### 1. Free pilot limit

Do not default to multiple free clients.

Recommended ladder:
- Client 1: free or symbolic pilot if ideal fit
- Client 2: discounted founding rate
- Client 3: stronger pricing discipline

### 2. Good pilot client criteria

A good pilot client is:
- ambitious
- thoughtful
- overloaded with ideas or inputs
- willing to engage seriously
- willing to give feedback
- a real fit for decision and execution systems

### 3. Bad pilot client criteria

Avoid clients who:
- are flaky
- want therapy or motivation instead of structure
- are low-agency
- are obviously not a fit
- do not value systems or follow-through

### 4. Pilot expectations

The client should know this is a structured setup sprint, not magic.

The pilot is meant to:
- create a clearer operating system
- improve ranking and prioritization
- reduce idea sprawl
- increase execution discipline

### 5. What to request in return

For a strong free or discounted pilot, ask for:
- honest feedback
- permission to use anonymized learning
- testimonial or endorsement if real value is created
