# How Veritas Operates

> Archived note. This document reflects a prior operating branch. Keep it as history, not active doctrine. Veritas core identity still stands, but current live operating rules are in `SOUL.md`, `IDENTITY.md`, `AGENTS.md`, `MEMORY.md`, and `FINANCE_SOUL.MD`.

## Why this document exists

This document explains, in plain language, how Veritas is operating so Randall can keep up with the system without needing to infer technical details.

## What Veritas is trying to do

Veritas is not trying to be a chat toy. The goal is to become a reliable AI operator and partner that helps Randall build real capability, real systems, and real monetary outcomes.

That means Veritas is trying to:
- tell the truth directly
- maintain continuity across sessions
- build useful workflows
- stay proactive
- move from ideas into measurable outcomes

## What Veritas is using

Veritas is mainly using:
- Markdown files in the workspace as the operating system
- Obsidian as the reading and navigation layer over those files
- memory files for continuity
- cron jobs and heartbeats for maintenance and review
- upgraded skills for more reliable specialized work

## Why Markdown is the source of truth

Markdown is currently the best source of truth because it is:
- fast to create and edit
- easy to read
- easy to search
- easy to version with git
- easy to open in Obsidian
- easier to maintain than premature software

Word documents are still possible later, but they should be treated as export artifacts, not the live operating system.

## How Veritas thinks about work

Veritas is trying to separate work into layers:

### 1. Core operating files
These define identity, behavior, continuity, and environment.

Examples:
- `SOUL.md`
- `AGENTS.md`
- `USER.md`
- `TOOLS.md`
- `MEMORY.md`

### 2. Daily memory
This captures what actually happened during the day.

Example:
- `memory/YYYY-MM-DD.md`

### 3. Dashboards and departments
These turn ideas and workflows into readable structures that can be reviewed and acted on.

Examples:
- `01. Dashboards/`
- `04. Departments/`
- `02. Opportunities/`
- `03. Offers/`
- `05. Plans/`

## Why Veritas is making training documents

Randall explicitly said he is learning from all of this and needs to be able to keep up.

So Veritas should not assume that Randall automatically knows every tool, skill, structure, or system choice.

Training documents exist to:
- explain what is being built
- explain why it is being built
- explain how to review it
- reduce confusion
- make the system teachable and repeatable

## What success looks like

Success is not a large pile of notes.

Success means:
- the system stays understandable
- the system creates action
- the system leads to monetization, learning, and better decisions
- Randall can review the system in under an hour and still understand where things stand
