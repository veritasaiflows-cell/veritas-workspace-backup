assistant: Short version: the pre-dispatch gate is the direct efficiency feature. The other items make that optimization safe, reliable, and diagnosable.

| Item | What it does | Efficiency/speed benefit |
|---|---|---|
| Status Card pre-dispatch gate | Checks whether the Status Card inputs actually changed before running the five-step refresh chain. | Unchanged work becomes a fast no-op. It “makes unnecessary runs disappear.” |
| Focused regression tests | Verifies skip logic, failure handling, path safety, timestamps, counters, and authority boundaries after code changes. | No runtime speed gain, but prevents regressions and costly repair cycles. |
| 63 explicit inputs hashed | Checks a fixed manifest of relevant scripts, documents, packets, state, and recent memory—not the whole workspace. Volatile timestamps are normalized away. | Keeps preflight bounded and avoids running the full chain when relevant inputs are unchanged. |
| Required/optional failures separated | Missing critical code/control inputs force a run. Missing noncritical packets create a warning but can still reuse a valid result. | Prevents both unsafe skipping and needless repeated runs caused by harmless missing packets. |
| Only successful, fresh output reused | Reuse requires an exact successful runner result within the 45-minute window. | Acts like a bounded cache: safe reuse during the window, automatic refresh after expiry or failure. |
| Strict five-step counters/timestamps | Requires exact `5/5` execution, no failed steps, and a valid non-future timestamp. | Prevents false-green results that would create downstream rework or stale decisions. |
| Workspace-bound proof/output paths | Prevents `--out` or `--runner-out` from writing outside the workspace. | Primarily safety, but avoids accidental corruption, recovery work, and failed output paths. |
| Custom output forwarding/nested directories | Ensures the selected runner output path is actually used and its parent directory exists. | Prevents reports from describing stale output and reduces retry/debug time. |
| Structured failures | Converts timeout, launch, nonzero exit, malformed output, and stale output into explicit proof states. | Failures become immediately diagnosable instead of silently failing or requiring blind retries. |
| Explicit review-only boundaries | Blocks cron/config/runtime, finance, portfolio, brokerage, paper/live execution, external delivery, and approval mutations. | No direct speed gain; it lets us automate the safe part without creating authority or operational risk. |
