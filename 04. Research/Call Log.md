# Call Log

## Purpose

Track every directional stance made by this system against its eventual outcome. This is the feedback loop.

Without outcome tracking, there is no way to know whether the analytical process works. Good calls and bad calls are indistinguishable in retrospect without this record.

## Rules

- Every formal execution stance from the Execution Board becomes a logged entry when it is first made
- When a name's status changes materially (entry hit, stop hit, earnings changed the thesis, regime changed), log the outcome
- Review quarterly — not to punish bad calls, but to identify systematic biases in the process
- A call is "correct" if the thesis played out as stated within the timeframe, regardless of whether an actual trade was made
- A call is "incorrect" if the stated thesis failed within the timeframe or the stop was hit

## Scoring

- **Correct:** Thesis played out, price moved in stated direction within timeframe
- **Incorrect:** Thesis failed, stop hit, or material thesis impairment
- **Incomplete:** Still open, no resolution yet
- **Voided:** External event (earnings, macro shock) changed the frame before the setup could resolve
- **Superseded:** Later evidence, earnings, owner decision, or canonical band/stop update changed the decision frame. Preserve the original call text, close the stale frame, and exclude from hit-rate/probability evidence.

## Quarterly review format

At the start of each quarter, run this review pass:

1. Count correct / incorrect / voided calls
2. Identify any systematic bias (e.g., too early on pullback calls, too conservative on breakouts)
3. Note whether the 5-gate framework was applied consistently in each case
4. If a call was wrong, identify which gate failed — thesis, macro, technical, catalyst, or risk/sizing
5. Update the operating model or deployment rules if a pattern of failure repeats
