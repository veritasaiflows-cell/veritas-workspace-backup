**How It Works**

Current slow path:

```text
Go command -> starts external sqlite3.exe -> SQLite DB -> returns rows -> Go parses JSON
```

That creates process-startup overhead every query.

Better path:

```text
Go command -> opens SQLite DB directly in memory/process -> runs query -> returns rows
```

So the Go binary becomes its own tiny backend for that command. It does not need a web server, daemon, API service, or always-running process.

**What Changes**

We add a Go package like:

```text
scripts/go/internal/sqlutil
```

with two modes:

- `cli`: current fallback using `sqlite3`
- `inprocess`: new direct SQLite driver mode

Then commands can run like:

```powershell
cd scripts\go
go run .\cmd\go-sql-latency-probe --root ..\.. --driver inprocess --iterations 20 --out ..\..\tmp\go-sql-latency-probe.json
```

Later, if proven stable, default becomes `inprocess`, and `cli` remains fallback.

No.
