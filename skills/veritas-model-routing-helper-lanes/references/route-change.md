# Approved Route Change

Read when applying an owner-approved change to OpenClaw model routing (the global default `agents.defaults.model` or an agent's `model`), or when a routing validator, fleet policy or generated packet reports drift after such a change. Diagnosing why a route reuses prompt cache poorly is owned by [Route Cache Reuse Review](route-cache-reuse-review.md); this reference owns applying the change and reconciling the result.

1. **Pin the approval and the exact ordered target.** Convert the request into an explicit before/after ordered list, distinguishing primary, each fallback position, and explicit removals. Record the approval source. **Done:** the exact target order and its approval are recorded, and any requested removal is stated as a chain removal rather than a model deletion.

2. **Apply through the scoped configuration procedure** owned by Persistent Agent Registration (the `persistent-agent-registration` skill) - `openclaw config patch --file <patch.json> --dry-run` first, then the same patch on a clean preview. A patch's object merge **replaces arrays**, so a `fallbacks` list must be complete in one patch. A model removed from the chain still sits in `modelPolicy.allow`, `agents.defaults.models` and the provider catalog, so it remains explicitly selectable; report that residual surface instead of implying the model is gone. **Done:** dry-run previewed, change applied, and residual selectable refs named.

3. **Verify the applied state by reading it back, never by the command's exit status.** Re-read the parsed value (`openclaw config get <path>`) and run `openclaw config validate` as its own evidence. **Done:** the parsed postimage equals the approved order and validation passes independently.

4. **Compare the applied value against the workspace's canonical routing policy before calling the change consistent.** Live config and policy files can disagree: `scripts/agent_fleet_policy.py` owns `MAIN_PRIMARY`, `MAIN_FALLBACKS`, `SPECIALIST_PRIMARY` and `LEGACY_DENIED_MODELS`, and `scripts/project_implementation_router.py` plus `skills/long_work_packet_linter.py` derive their expectations from it. A live primary outside that policy makes Main-route packets emit `main_model_invalid` / `main_live_model_mismatch`, and a policy-denied model in a persistent specialist role is rejected. **Done:** the live value is compared with the policy value and every mismatch is named with its validator code.

5. **Attribute drift to this change or to history before claiming you caused it.** Run the same validator against the OLD value, the NEW value and the policy target separately. A value already rejected before the change is pre-existing drift, not a regression; say so plainly rather than accepting blame that would mislead the repair decision. **Done:** each tested value's validator result is recorded and the drift is labelled new or pre-existing.

6. **Keep canonical-policy reconciliation a separate owner-gated change.** Policy constants, router and linter matrices, and their tests are protected core surfaces; a routing approval does not authorize editing them. Present the options - reconcile policy to live, revert live to policy, or carry the drift knowingly - and name which one needs which approval. **Done:** options and their gates stated, with no policy file edited under a routing-only approval.

7. **Confirm the effort lever matches the request rather than assuming a per-model key.** Per-model model settings accept only `alias`, `params`, `agentRuntime`, `codeMode` and `streaming`; there is no per-model thinking key, so a requested effort level applies through `agents.defaults.thinkingDefault` or a per-agent `thinkingDefault`. Read the effective default first: if it already equals the request, report it as already satisfied instead of applying a no-op edit. **Done:** the effective default is read from config and the request is satisfied or explicitly reported as needing a different lever.

Close with the applied order, read-back proof, the drift verdict and its attribution, the residual selectable refs, and every owner-gated item. A route change grants no capital, execution, channel or authority change, and this reference never applies a policy edit.
