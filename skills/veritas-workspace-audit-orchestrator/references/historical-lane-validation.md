# Historical Lane Validation

Use for full-register validation errors, especially when active lease admission passes. This is a read-only diagnosis and repair recommendation, not a lease transition or ledger-cleanup procedure.

1. Inspect `scripts/concurrent_lane_manager.py` before execution: verify the status path, write gates, register path and validation functions. Record register/validator SHA-256 hashes and scoped Git status. Run `python -B scripts\concurrent_lane_manager.py --status --active-lease-safety --validate` without `--write`, capturing its exit code. Finish with separate full-validation and active-admission results; zero active lanes or admission `ok` does not clear terminal-record debt.

2. Extract bounded failure detail, not the whole register or warning inventory. The CLI prints error/warning counts rather than full-register failure rows. With the verified module on `sys.path`, use `load_register(DEFAULT_REGISTER)` and `validate_register(register, usage_receipt_store_path(DEFAULT_REGISTER))` in memory. Print critical check names and their affected lane/path details; summarize each warning by name, row count and at most one example. For dictionary details, count its `gaps` list; for list details, count the list. If critical detail is large, select one failing check at a time. Use `python -B` and stdout rather than writing or refreshing the register. Finish with the exact failing check and record; large historical warning dumps can otherwise truncate the critical result.

3. Open only affected records and the predicate that rejected them. For missing proof, inspect `proof_artifacts`, terminal status, creation/completion timestamps, acceptance and durability fields, the proof-path resolver and its enforcement cutoff. Distinguish post-cutoff missing proof from pre-cutoff warning inventory. Preserve dates, outcomes and unavailable evidence; do not remove proof references, relabel completion, move cutoffs or weaken checks to obtain green. Finish with the actual failed condition, separate from other recorded incidents and current lease safety.

4. Resolve the exact missing file and parent directory, then inspect only plausible siblings, declared archive relocations and backup/history sources. Include ignored files in a bounded filename search: `tmp/` can be Git-ignored, so ordinary `rg --files` or Git history alone cannot establish absence. Report the searched scope. A cleanup script naming the directory proves a possible deletion path, not execution or causation; require a retained execution receipt before attributing the loss. Finish with an authenticated recovery candidate or an explicit original-not-found limit.

5. Recommend restoration only of an authentic original whose provenance/content can be verified, under a separately scoped write decision. Preserve the historical record and unrelated work; do not regenerate today's test results at yesterday's proof path or retarget the reference to unrelated evidence. A fresh test can establish current behavior only. If no authentic original is available, retain the error and state the evidence gap rather than invent a repair. Finish with a conditional restoration proposal or a truthful unresolved disposition, never a claimed recovery not performed.

   When no authentic original exists and the owner directs the register repaired, the honest amendment is schema-constrained, so follow the validator's exact semantics rather than improvising. Back up the register byte-exactly with its sha256 recorded first. Set the lane's `proof_artifacts` to an empty list — an empty list passes the existence check because the per-proof loop runs zero iterations, and the completed-lane check stays satisfied by its `acceptance_commands`; there is no `proof_artifacts_status` field in the schema, so carry the lost path in a new truthful `proof_artifacts_lost` field with a not-recoverable classification rather than deleting the reference silently (this reconciles with step 3: the path and the loss stay recorded, so nothing is removed to obtain green). Append the outcome event as a bare row of exactly `event_kind`, `event_sequence`, `recorded_at_utc` — the sequence must equal its 1-based index, timestamps strictly increase, and the `runtime` mirror must reflect the last row; a row enriched with detail keys fails `outcome_event_metadata_is_bounded_and_complete`, which is why the detail belongs in the loss field, not the event row. A lane created after the proof-enforcement cutoff earns no historical classification, so the empty list is the only schema-valid honest repair. Finish by byte-comparing against the backup to prove exactly one lane changed, rerunning the full validator, and refreshing downstream consumers that read the register. Verified 2026-09-22 on a completed lane whose only proof artifact was deleted post-completion: the amendment passed validation with zero errors, exactly one lane of 1,846 changed, and the downstream coding-outcome ledger returned to `ok`.

6. Recheck register/validator hashes and active-lease state at closeout. Investigate drift rather than overwriting concurrent work. Report full validation, warning categories, active admission, search limits and any actual changes separately. A later authorized restoration must rerun the original full gate and active admission independently; clearing one critical error does not erase remaining warnings or establish Main acceptance.
