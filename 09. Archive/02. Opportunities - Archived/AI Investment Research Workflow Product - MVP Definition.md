## Product goal

Create a reliability-first research workflow that helps a serious individual investor or operator move from scattered ideas to ranked opportunities and concrete next actions.

## Exact first user

The first user is Randall.

Profile:
- intelligent, opportunity-driven, tech-literate
- interested in AI, investing, business, and monetization
- strong at analysis and idea generation
- weak point is overbuilding, overlearning, and not always converting insight into action

This matters because the MVP should first solve Randall's real workflow pain, not an imagined mass-market problem.

## Exact pain

The problem is not lack of information.

The problem is:
- too many possible opportunities
- not enough ranking
- not enough forced action
- overresearch without execution
- weak conversion from insight to monetizable movement

## First workflow

### Workflow name
Opportunity Intake -> Research -> Scoring -> Decision -> Next Action

### Input
A possible opportunity, such as:
- a public equity idea
- an AI tooling thesis
- a product concept
- an acquisition concept

### Process
1. capture the opportunity
2. classify the category
3. write a short thesis
4. score reliability and upside first
5. identify key risks
6. choose one next action
7. rank it against the current pipeline

### Output
A decision-ready opportunity note with:
- thesis
- score
- rank
- risks
- next action
- status

## Narrow MVP

The MVP is not a full platform.

It is:
- the Opportunity OS in the vault
- a repeatable note template
- a scoring rubric
- a ranked pipeline
- one weekly review loop
- Veritas acting as the operator that keeps the system honest and current

## What the MVP must do well

- reduce idea sprawl
- force prioritization
- force a next action
- keep one major active project
- create visible movement toward side income

## What the MVP should not try to do yet

- full automated market scanning
- advanced financial modeling
- brokerage execution
- portfolio management suite
- broad multi-user SaaS
- giant agent swarm architecture

## Monetization hypothesis

First value path:
- use internally to improve decision quality and action speed
- shape it into a productized research workflow, premium template system, advisory workflow, or AI-assisted operator service

Fastest likely monetization path:
1. internal operating advantage
2. productized workflow or consulting/advisory offer
3. software product if repeated pain proves real

## First success criteria

Within the next few weeks, the system should produce:
- a ranked pipeline that stays current
- at least one clearly chosen primary opportunity
- measurable reduction in scattered idea handling
- real next actions taken, not just better notes

Within 3 to 6 months, it should contribute to:
- side income
- monetizable workflow IP
- stronger research discipline
