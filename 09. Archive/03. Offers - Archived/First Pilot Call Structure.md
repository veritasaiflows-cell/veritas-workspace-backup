# First Pilot Call Structure

> Archived note. This file belongs to a retired operating branch. Preserve it as historical context, not current doctrine. Current live identity and operating rules are defined by SOUL.md, IDENTITY.md, AGENTS.md, MEMORY.md, and FINANCE_SOUL.MD.

## Goal

Use the first real follow-up engagement to turn their concerns into a structured operating-system setup path.

## What this session should produce

By the end of the session, you should have:
- a clear inventory of active ideas, projects, or priorities
- a clear diagnosis of where execution breaks down
- draft ranking criteria
- an outline of the workflow/dashboard structure they need
- a defined next engagement or sprint path

## Recommended flow

### Part 1. Reconfirm the problem
- summarize what you heard on the discovery call
- ask whether that diagnosis still feels accurate

### Part 2. Inventory the moving pieces
- list active projects, ideas, priorities, and obligations
- separate current commitments from possible future opportunities

### Part 3. Define decision logic
- identify what makes something high priority
- identify what should be delayed, delegated, or dropped
- draft the first ranking criteria

### Part 4. Define the operating system shape
Decide what they need:
- a dashboard
- a workflow
- a weekly review rhythm
- a way to track and rank priorities
- a way to convert priorities into execution

### Part 5. Define the next paid or pilot step
Propose the next engagement clearly.
Example:
- I would recommend a focused 1-week setup sprint where we build the first version of this system and leave you with a repeatable operating rhythm.

## Rules

- Do not promise a perfect system in one call.
- Do not jump into tool complexity too early.
- Do not confuse a diagnosis call with full implementation.
- End with a clear next step, not a vague maybe.
