# 2026-09-15

> Backfilled 2026-09-16 evening. No daily file was written on the day itself because the gateway was down through the morning. Every fact below is evidenced; the analysis was done on 09-16 and is recorded in full in `memory/2026-09-16.md`.

## Windows Update reboots took the gateway down and cost the market open

- The System event log shows `TrustedInstaller.exe` and `MoUsoCoreWorker.exe` initiated **three reboots between 00:29 and 00:32**, matching an identical pattern on 09-09. Every recorded outage to date is a Windows Update restart.
- `ActiveHoursStart=6` / `ActiveHoursEnd=0` permits reboots 00:00-06:00 Phoenix — exactly the window these landed in. Active hours are already at the 18-hour maximum, so the range can be shifted but not widened.
- **Functional outage was roughly 7.3 hours, 00:31 to 07:50**, established from cron run history rather than scheduled-task metadata: the morning chain (`Finance - Weekday Morning Alerts and Recommendations Refresh`, scheduled 06:05) ran **07:50:54**, intraday freshness succeeded continuously from 09:30, post-close ran 13:20.
- **The open was still lost.** The morning refresh landed 1h45m late, after the 06:30 open.
- Unresolved: the gateway `node.exe` was created **19:13:05**, which a 07:50 recovery does not explain. The two logs that would settle it are unreadable or disabled.
- ARSO was already enabled (`AutoLogonSID` equals Randall's SID) and did **not** prevent the outage.

## Consequences that surfaced later

- 09-15 is **not credited** toward G8; the observation window was restarted with Day 1 = 09-17.
- Several control-plane cron jobs began failing on this date and stayed failing: `Cron Reduction - Control Fail-Closed Dispatcher`, `Runtime - Future Session Packet Refresh`, `Macro - Energy and Geopolitical Inputs Refresh`, and `Ops - OTEL Local Digest` (21:40). Root causes were diagnosed on 09-16 and are mostly unrelated to the reboot itself — see the 09-16 entry.

## Durable lesson

Use **cron run history** as the outage oracle. Scheduled-task `LastRunTime` and process `CreationDate` answer different questions and both produced wrong outage durations when used here.
