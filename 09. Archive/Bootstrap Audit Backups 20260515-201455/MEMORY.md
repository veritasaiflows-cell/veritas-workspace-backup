## Durable Lessons Worth Keeping

- If something matters, write it down. No mental notes.
- A tool or workflow is not truly ready until binary, auth, config, and actual runtime behavior are all verified.
- On Windows, scheduled automation and environment variables can drift; verify live process reality, not assumed setup.
- Readiness audits expire. Revalidate old successes and old failures before relying on them.
- If strategy changes, dashboards, memory, and navigation must change with it or the system becomes misleading.
- Artifact coherence matters as much as individual script success.
- Lightweight validators are worth keeping when a workflow has recurring drift points.
- When a shared state vocabulary or JSON contract changes, scan adjacent consumers and validators before calling the pass closed; the real drift often lives in downstream fallthrough logic, ranking maps, or stale acceptance assumptions rather than the first patched file.
- Stop-breached and near-stop states must outrank softer watch, almost-deployable, owner-approved-history, or band-review language in generated finance surfaces and owner notes; make the stop/band math explicit so Randall does not have to infer invalidation risk manually.
- After code changes that affect freshness- or trust-sensitive artifacts, regenerate or freshen the proof surface before judging closure; stale fixture timestamps can create fake-red residue.
- Workflow continuity names can drift across rewrites; verify the exact live filename/path from the workspace before claiming a workflow is missing, blocked, or renamed.
