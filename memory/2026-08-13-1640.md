assistant: P2’s benefit is not “more telemetry for its own sake.” It turns agent work into accountable operating data: what ran, for which parent job, on which model, how much it consumed, whether it was accepted, and whether it was actually more efficient.

How it works

Main job → bound dispatch record → agent run → source receipt → independent verification → scorecard

1. Before dispatch, the system creates a privacy-safe identity for the work:
parent job, lane, phase, attempt/retry, intended model/backend, budget, and a hashed session/run reference.

2. The dispatcher writes the same binding into the agent’s real source record before it starts. That is the missing link today. A routing suggestion or a lane note will no longer count as proof that an isolated agent was used.

3. At completion, the source reports its terminal metadata: actual model/runtime, start/end time, token categories, cache use, status, and cost only if the provider exposes it.

4. The verifier reopens that source record and requires a one-to-one match to the original job/lane/attempt. If anything is missing, ambiguous, stale, reused, or contradictory, the run stays visible as audit evidence but earns zero cost, savings, quality, or performance credit.

5. Only verified runs enter the scorecards. They can then show cost/tokens, elapsed time, retries, cache efficiency, Main acceptance, QA outcome, and comparable results by model and task type.

Benefits

• Real per-job accountability. We will know whether an isolated agent was actually dispatched versus merely configured or suggested, and what it cost.

• Honest savings measurement. We can compare like-for-like completed jobs: Terra-default integration versus an explicit Sol challenger/QA escalation, using gross tokens, cached replay, elapsed time, retry tax, acceptance rate, and actual billed cost when available.

• Better routing decisions. Terra becomes the normal integrator; Sol’s higher-judgment use is deliberate and traceable. That lets us test whether Sol materially improves difficult QA/challenger work enough to justify its incremental spend. We will not assume either model is cheaper or better before the data supports it.

• Faster waste detection. Duplicate dispatches, excessive context replay, repeated failed attempts, unused configured agents, and expensive use on routine tasks become visible quickly.

• More reliable automation. “Provider usage unavailable” stops being a vague after-the-fact gap. It becomes a named blocked condition with an owner and repair path, rather than being silently treated as a completed or efficient job.

• Better governance without surveillance. Captured fields are metadata only: IDs, model/runtime, timing, counts, outcome class, and cost status. No prompts, responses, hidden reasoning, tool payloads, secrets, account data, or trading instructions are collected.

What it will not do

• It will not backfill the existing 597 gaps or invent historical savings.
• It will not guarantee actual billed cost if the provider does not expose job-scoped billing. In that case we will show “unavailable,” not estimate it as fact.
• It will not change finance authority, capital deployment, paper/live trading, or cron schedules.

How we measure success

For each route/model/task cohort, we establish a baseline and wait for enough comparable Main-accepted jobs (at least 10) before making routing claims. Then we report:
- verified coverage rate;
- cost/tokens per accepted job;
- elapsed time and retry rate;
- QA yield and escaped-defect rate;
- savings versus the matched baseline, with confidence limits.

So the immediate payoff is truth and control. The later payoff is evidence-based savings: we can reduce cost or improve quality only where the measured data proves it.

What P1 fixed

Before P1, a fresh Tier A/B price could enter its entry band after the last refresh, yet the 15-minute controller only looked for stale quotes. It could return “no action,” leaving a real review candidate invisible.

P1 changes that.

How it works — every 15 minutes

Fresh quote
→ compare against the current Tier A/B entry band
→ if the price is newly in band, rerun band hygiene and technical/decision sync
→ create or refresh an in-band review-attention item
→ apply a short-lived intraday review overlay
→ refresh targeted official earnings/evidence for that exact ticker
→ rebuild the ranked WF85 review queue, even on a quiet pass.

The overlay expires after 15 minutes. If it is not refreshed by valid evidence, it degrades back to repair/monitor status instead of lingering as a false “current” recommendation. Unchanged issues are deduplicated, so it does not spam you.

• No more silent missed review windows. GOOG, CAT, and ECL now surface automatically when their fresh prices enter band.
