I walked the chain end-to-end (run_finance_refresh_chain.py → 25 steps → tmp/*.json → dashboard_payload.py → veritas-command-center.html + workbook CSVs) and inspected every artifact under tmp/. Here's what's actually happening and the gaps you're seeing.

Root cause of the watchlist ↔ trigger-sheet ↔ dashboard mismatch
There are three different definitions of "the universe" baked into the chain, all reading the same tmp/portfolio-config.json but with different filters:

Stage	Filter	Output count
entry_bands (band_refresh, validator)	all keys in entry_bands	17 (incl. CVX, PLTR, KTOS, SLV)
technical_refresh.py	include_in_technical_refresh == True	13
trigger_sheet_refresh.py	include_in_trigger_sheet == True AND ticker in deployment_check	13
dashboard_payload.technical[]	iterates technical-refresh.json records	13
workbook-watchlist-board.csv	iterates trigger-sheet	13
So CVX, PLTR, KTOS, SLV carry full entry bands, get drift proposals (band-update-log.txt), and trip the validator ("10 entry band(s) need review … CVX, PLTR, KTOS, SLV") — but they are silently filtered out before they reach the trigger sheet or dashboard action cards. The operator sees a warning to review them, with no UI surface to act on.

This is a schema problem, not a data problem. portfolio-config.json has at least three opt-in flags (include_in_technical_refresh, include_in_trigger_sheet, presence-in-entry_bands) and they have drifted.

Other gaps in the orchestration
Note-layer drift: band-note-sync.md shows 6 names (ETN, GOOG, AMZN, VRT, RTX, CAT) with sync needed — the JSON entry bands have been advanced by apply_band_update.py but 03. Portfolio/Technical Entry and Invalidation Sheet.md has not. This is a one-way pipeline; there's no gated writer-back, so the canonical note silently rots after every band refresh.
earnings_policy: block_pre_earnings is window-blind: AMZN (91d), GOOG (84d), MSFT (90d) are all flagged "BLOCKED" with earnings months away. Validator catches it as a warning but the trigger sheet and dashboard still mark them blocked, masking otherwise-actionable setups.
Macro/policy soft failure: policy_expectations_refresh.py CME endpoint returns 404 → falls back to manual Fed-target constant; fallback_state.used: true on every run, presentation_allowed: false, canonical_note_mutation_allowed: false. The whole chain is locked into "warning" mode by an upstream data source.
No consistency-gate step in the chain: nothing verifies that tracked_universe.keys() == entry_bands.keys() == trigger-sheet ticker set == technical-refresh ticker set before the dashboard is generated. Today's mismatch slipped through silently.
--strict only routes to validate_dashboard_state.py — not to test_dashboard_acceptance.py or workbook_export.py, so a strict run still publishes degraded artifacts.
Workbook earnings tracker has 2 rows despite 3 blocked names with confirmed dates — workbook_export.py filtering is narrower than the dashboard's blocked set.
Speculative/macro tier (CVX, PLTR, KTOS, SLV) has no home on the dashboard — they're tracked, banded, drift-monitored, but invisible. No "Watch lane" or "Macro lane" surface.
