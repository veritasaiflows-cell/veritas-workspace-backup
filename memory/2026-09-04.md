## 20:55 MST - Astra recovered on the codex app-server route

**Randall's hypothesis was right, and the earlier entry above was wrong about the fix.** He upgraded global codex-cli to 0.153.4 and astra still failed; he said the problem was OpenClaw's own Codex version. **Why astra failed.** GPT-6 Astra launched 2026-09-03/04, days ago. OpenClaw 2026.9.1 predates it and has no catalog entry for it anywhere in its bundle - `gpt-6-astra` appears in `openclaw models list` only because it was hand-added to config. Two separate failures were in play:

It sends `originator: openclaw` and **no `version` header** at all (`@openclaw/ai/dist/openai-chatgpt-responses-*.mjs:992-1000`), even though `docs/concepts/model-providers.md:120,170` claims `originator`, `version`, and `User-Agent` are all attached. That is a real gap in this build. This route now fails earlier still, at `Unable to materialize openai/gpt-6-astra for its prepared subscription route`.
- The correct route is the **Codex app-server plugin**, where `plugins.entries.codex.config.appServer.command` was already pointed at the global 0.153.4 binary. That binary knows astra and sends its own proper headers.

**Fix applied** (backup `openclaw.json.pre-codex-astra-205115`): declared `codex/gpt-6-astra` in `agents.defaults.models` with `alias: astra`, added it to `modelPolicy.allow`, and removed the dead `openai/gpt-6-astra` model definition and allow-list entry. Verified: `codex/gpt-6-astra` and the `astra` alias both return `ASTRA_OK`, `winnerProvider: codex`, `fallbackUsed: false`, success on first attempt.

**Rejected approach.** Spoofing `originator: codex_cli_rs` or a fake version header by patching the bundled client. That is impersonation, and it turned out to be unnecessary.

**Tested and reverted.** Adding `models.providers.openai.headers.version = "0.153.4"` does reach the request (provider headers flow through `model.headers` and `version` is never overwritten), and terra ran clean with it, but it did not fix astra. Reverted; no trace left in config.

**Default unchanged.** Terra remains primary per Randall's instruction and re-verified `DEFAULT_OK` / `winnerModel: gpt-5.6-terra` / `fallbackUsed: false` after all edits. Astra was deliberately **not** added to the fallback chain - it is $10/$50 per million tokens, so that is Randall's call, not an automatic promotion.

**Separate pre-existing defect found, not caused by these edits:** `codex/gpt-5.3-codex-spark` (alias `spark`) fails with `No API key found for provider "codex" | missing-provider-auth`. Proven pre-existing by restoring the exact pre-change config and reproducing the identical error. It has `agentRuntime: {id: codex}` and needs a `codex` provider credential that is absent from the auth store; astra works because it resolves through the plain provider path on the existing OpenAI OAuth profile. Unresolved and unowned.

**Lesson.** Same model id under two provider prefixes can take completely different transports with different auth and different version gating. `openai/X` and `codex/X` are not interchangeable. When a vendor error says "upgrade your CLI", check which client actually issues the request before trusting the message.
