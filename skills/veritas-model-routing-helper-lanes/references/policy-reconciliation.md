# Policy Reconciliation

Read when the owner has explicitly authorized reconciling the canonical routing policy to the live configuration - the "reconcile policy to live" option from [Approved Route Change](route-change.md) step 6. Applying the live route change is owned by [Approved Route Change](route-change.md); applying the config itself is owned by Persistent Agent Registration (the `persistent-agent-registration` skill). This reference owns editing the policy owner and its derivations.

1. **Confirm the approval names the policy files, not just the route.** A routing approval authorizes the chain; it does not authorize protected core surfaces. Require an explicit owner authorization before editing the policy module, the router/linter matrices or their tests; if it is absent, stop at the presented option set. **Done:** the authorization scope is recorded, or the work stops without touching a policy file.

2. **Inventory every consumer before editing, then classify each hit.** Search each policy constant name (`MAIN_PRIMARY`, `MAIN_FALLBACKS`, `MAIN_MODEL`, `SPECIALIST_PRIMARY`, `SPECIALIST_RECOVERY`, `LEGACY_DENIED_MODELS`) across the repository and classify every result: *derivation* (reads the constant, so it follows automatically and only needs verification), *literal mirror* (hardcodes the same value and must be edited), *content lint* (a validator whose substring/regex denial scan covers whole artifact text; when a previously denied model becomes the Main primary it legitimately appears in generated `model_route`/bootstrap text, so the lint false-fires - fix the rule to strip the policy Main-primary value before scanning, preserving denial for the role's own model and recovery positions; evidenced 2026-09-26, Opus 5.5 realignment, `agent_bootstrap_linter.py`), or *frozen binding* (approval/hash-bound and must not be touched - step 7). **Done:** a per-hit classification that names the derived surfaces separately from the edited ones.

3. **Prefer deriving a consumer over mirroring a literal.** Where a consumer hardcodes a role's model, replace it with a policy lookup and add one named alias beside the existing aliases instead of editing literals at each use site, so the consumer follows subsequent policy changes. **Done:** the consumer resolves the policy value and no duplicate constant was introduced.

4. **Change the constants and keep denial semantics scoped.** Removing a model from the denied set is right when it becomes the live primary, but keep other retired refs denied, keep persistent-specialist scope denied, and keep an advisory-only model out of specialist automatic fallbacks even when it legitimately sits in the Main chain. Record the scoping decision and the approval id in the policy header. **Done:** every constant's new value is stated and every retained denial has a stated reason.

5. **Mirror the change into the fixtures that encode the old value, and label those edits as alignment.** Expected-value tests, example packets and guidance strings carry the previous value literally; updating them changes no behaviour, so attribute each edited expectation as fixture alignment rather than a behaviour change. **Done:** every touched expectation is attributed as alignment with behaviour unchanged.

6. **Attribute each test failure by replaying the pre-edit values; do not assume version-control HEAD is the baseline.** An uncommitted change may already have moved the same values, so HEAD is not reliably the pre-change state. Replay instead: in a scratch process, patch the policy module's constants back to their previous values *before* importing the dependent module, run the failing suite, and compare failure sets. A failure present under both is pre-existing history, not a regression; report it as such rather than claiming or accepting it. (Separating committed from uncommitted source for a patch review is the different purpose of [source-defect-verification](../../veritas-os2-cleanup-router/references/source-defect-verification.md).) **Done:** for each suite, the failure set under the pre-edit values is recorded and every failure is labelled new or pre-existing.

7. **Leave hash-bound frozen contracts as historical evidence.** A contract module carrying an approval hash and a fixed expiry window is bound to the snapshot it was approved against; any byte change breaks that binding. A stale constant inside it is history, so record it and require a new approved contract instance instead of an in-place edit. Full procedure: [Task-Role Contract Review](task-role-contract-review.md#frozen-task-role-contracts). **Done:** frozen modules are unedited and named as remaining history.

8. **Verify agreement across every derivation before closing.** Assert that the policy, the bootstrap generator, the router and the linter resolve the same main model, fallback order and role primaries, that the map validator reports agreement, and that the affected suites and the example validator still pass. Close with the new-versus-pre-existing attribution, the replay evidence for each remaining failure, and any still-open owner-gated item. **Done:** an alignment check reports agreement and no remaining failure is left unlabelled.

Reconciliation grants no capital, execution, channel or authority change. It edits the routing policy to match an already-approved route; it never re-orders the live chain, which stays with [Approved Route Change](route-change.md).
