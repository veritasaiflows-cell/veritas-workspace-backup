**How It Works**

OpenClaw isolated agents have their own configured workspace and `agentDir`. Current config shows:

| Agent | Workspace | Sandbox |
|---|---|---|
| `main` | inherits `C:\Users\Veritas\.openclaw\workspace` | none configured |
| `research-scout` | `C:\Users\Veritas\.openclaw\workspaces\research-scout` | none configured |
| `qa-redteam` | `C:\Users\Veritas\.openclaw\workspaces\qa-redteam` | none configured |

OpenClaw docs say the workspace is the agent’s **default cwd**, not a hard sandbox. Relative paths resolve inside that agent’s workspace, but absolute paths can reach other host locations unless sandboxing is enabled. The web docs and local installed docs agree on that.

So:

```text
06. Playbooks\Agent Knowledge Base\index.md
```

from `research-scout` would resolve inside:

```text
C:\Users\Veritas\.openclaw\workspaces\research-scout\
```

But this absolute path:

```text
C:\Users\Veritas\.openclaw\workspace\06. Playbooks\Agent Knowledge Base\index.md
```

points back to the main Veritas workspace, and the isolated agents can read it if they are given/allowed filesystem read tools.

They do **not** automatically receive the Agent Knowledge Base in their prompt.
