# Startup Truth Index

Thin startup and post-compaction route. It points to canonical owners; it does not replace them.

## Authority

- `SOUL.md`, `AGENTS.md`, and `USER.md` own always-loaded doctrine. `AGENTS.md` includes the local runtime and route map. `SOUL.md` owns identity; no live `IDENTITY.md` mirror is required.
- `MEMORY.md` owns curated durable continuity; daily memory owns chronology.
- Active Workflows, workflow state/capsules, and exact owner notes own current work truth.
- The alerts-and-recommendations canon and guarded SQL current state own finance/alert truth. Generated artifacts, wiki, and indexes route evidence only.

## Minimum Boot Path

1. Read `SOUL.md`, `AGENTS.md`, and `USER.md`, then this index.
2. Validate `tmp/current-resume.json` and `tmp/current-active-lanes.json` with `python -B scripts\session_resume_checkpoint.py --validate` before executing resumed work.
3. Classify recall, relationship, and tool-reference needs with the route below. Run only the branch that fits the request; graph loading is never mandatory startup work.
4. For a named workflow, run `python -B scripts\workflow_router.py WF## --answer summary` or read its fresh capsule before broad owner notes.
5. For material/high-risk work load `task-intake-contract`; for implementation/helper/QA load only the relevant owner skills and exact proof surfaces.

## Resume Transaction

- Precedence: active leased-lane checkpoint -> exact workflow checkpoint -> named continuity owner -> PM queue -> general status.
- Missing/stale lease or identity, hash drift, expiry, consumed receipt, or multiple unresolved pickups blocks execution.
- Exact-ID acknowledgement is idempotent; execution is not. A terminal receipt stays consumed until changed content creates a successor.
- Resume pointers, memory, and generated packets route work; they never restore authority or prove execution.

## Recall, Relationship, And Tool Reference Route

Classify before broad retrieval. Memory, graphs, wiki, indexes, packets, and tool catalogs are fast routing/evidence surfaces; they never replace a current owner or validator.

1. **Prior decision, continuity, person, date, or todo:** use semantic `memory_search` with `corpus=memory` for routine recall, then use bounded `memory_get` only for the needed excerpts. Use `corpus=all` only when the task genuinely needs compiled-wiki context; it is not a default or fallback. Verify any current claim against its live owner artifact.
2. **Code, workflow, skill, or document relationship:** check Graphify freshness/health first (`python scripts\memory_graph_maintenance.py --mode gate --write --validate`, then `python scripts\lib\graphify_router.py health`; maintained scope is `scripts/graphify-out` only — root graph is on-demand reference, skills graphs unbuilt), then use the smallest relevant relationship lookup (`query`, `path`, or `affected` with `--budget`). Verify the result against current source and exact owner files; graph edges are derivation-only.
3. **Current operational, finance, approval, or execution truth:** bypass broad semantic/graph retrieval and open the exact owner artifact or validator directly.
4. **Tool or procedure selection:** open the named owner `SKILL.md` and the exact linked `references/` item before using a specialized command or deferred tool. `AGENTS.md`'s local route map and `openclaw-operator`'s `references\workspace-route-map.md` own the workspace command map. Load an exact callable/tool schema when available; never guess flags, capability, or authority from a tool name.

Degrade honestly and keep moving through the safe route:

- If semantic retrieval is unavailable, partial, or times out, say so; use the dated memory file, `MEMORY.md`, workflow capsule, and live owner artifacts without claiming an unverified recall.
- If a graph is stale, unhealthy, missing, or noisy, use `rg`, the workflow router/capsule, and exact source owners instead. Do not rebuild a graph merely to answer an ordinary request.
- If an exact tool reference is missing, stay read-only or use the documented owner front door; do not improvise a material mutation.

Role default authorship and independent QA route through `veritas-model-routing-helper-lanes`; see that skill and the fleet policy for live IDs. This index does not pin Main models. Main selects a listed recovery candidate only in a NEW clean-context, separately identified attempt from a verified checkpoint with unchanged role/scope and actual-model proof. Refresh transport/runtime/lease evidence when changed or stale; a model option grants no readiness or authority. Review cannot use the patch-author model.
- Expected model must equal the selected agent's live configured primary for persistent dispatch; a recovery candidate does not bypass that gate or missing capabilities. Sol architecture and Opus advisory are on-demand Main-spawn roles, not persistent agents. Main's ordered global fallback chain (2026-09-22) is Opus 5.5, then Ollama Cloud GLM 5.3, then Ollama Cloud Kimi K3, then GPT-5.6 Terra last; Opus 5 is Main-spawn advisory only, and neither Opus 5.5 nor Opus 5 is an isolated-agent persistent primary or recovery fallback.

- Validation is proportional; Main alone verifies and accepts.
- Review efficiency on demand from available attribution, elapsed-time, retry, acceptance, and escaped-defect evidence. No fixed cohort pilot is required; automatic route promotion remains disabled.
- Multi-model work uses separate inference/session runs under one parent task; a model does not change mid-inference.
