# WF23 Phase 2 Fresh Brief and Decision-Point Contract - 2026-05-06

Define the exact allowed claim shapes for the three approved Command Center surfaces so fresh briefs, unresolved truths, and decision routing become more visible **without** turning dashboards into a second truth layer.

This contract does **not** authorize edits to those surfaces by itself.

## Governing rule
The dashboard layer remains an **orientation, routing, and access layer**.
It may expose:
- fresh brief availability
- unresolved truth status
- warning-grade freshness condition
- immediate review sequencing
- links to canonical reports and owner notes

It may not:
- decide deployment state
- decide thesis quality
- clear blockers on behalf of owner notes
- collapse conflicting owner notes into one cleaner dashboard claim
- promote packet or machine evidence into canon without a human-owned note already carrying that judgment

## Claim-shape vocabulary
Every Phase 2 dashboard sentence or bullet fed by WF21/WF22-style upstream outputs must fit one of these allowed shapes.

### A. Fresh brief signal
**Meaning:** a new packet, scorecard, weekly brief, or post-earnings interpretation exists and should be read.

**Allowed shape:**
- availability statement
- recency statement
- read-this-first routing statement

**Allowed examples:**
- "A new post-earnings scorecard exists for XOM; use it before changing energy posture."
- "The weekly brief was refreshed after the May 5 cluster; use it for the current synthesis."
- "A fresh packet exists for ETN, but deployment status still belongs to the trigger and weekly owner notes."

**Not allowed:**
- "The new scorecard clears XOM for redeployment."
- "The fresh brief confirms ETN is now deployable."

### B. Unresolved-truth warning
**Meaning:** a relevant fact path is incomplete, conflicted, stale, secondary-only, or still pending human confirmation.

**Allowed shape:**
- explicit degradation statement
- explicit owner-not-yet-resolved statement
- explicit evidence-quality limitation statement

**Allowed examples:**
- "Primary-source capture for ETN remains incomplete; keep this as review-only until the owner notes are updated."
- "NVDA timing still has a narrow confirmation gap; use the owner note before treating timing as settled."
- "A stale dashboard phrase was cleaned up, but final state still belongs to the weekly and portfolio owners."

**Not allowed:**
- "Likely resolved"
- "Probably fine now"
- "Fresh again" when the evidence is only warning-grade or partial

### C. Action-routing prompt
**Meaning:** the dashboard tells Randall what to review next or which note should be consulted before acting.

**Allowed shape:**
- read-owner-first instruction
- review-before-decide instruction
- inspect-warning / confirm-state instruction

**Allowed examples:**
- "Read the ETN post-earnings scorecard before changing any industrials posture."
- "Use the Deployment Trigger Sheet before treating JPM or NVDA as real adds."
- "Confirm the remaining stale-surface warning on the owner note before closing the issue."

**Not allowed:**
- "Add JPM now"
- "Close the blocker"
- "Promote GS to primary"
unless that state already exists in the canonical owner and the dashboard is only routing to it with explicit owner framing.

### D. Report-intelligence link
**Meaning:** the dashboard links to a report or owner note for fast retrieval.

**Allowed shape:**
- report exists / read here
- source-of-truth lives here
- use-this-note-for-full-context

**Allowed examples:**
- "Use Weekly Positioning Review for the canonical weekly operating map."
- "Use Weekly Intelligence Brief for the latest synthesis after the earnings cluster."
- "Read the scorecard note for the full post-earnings interpretation."

**Not allowed:**
- direct `tmp/` artifact links as canon
- links that imply the dashboard summary is equal in authority to the target note

### E. Derived orientation summary
**Meaning:** a short high-level summary of what changed materially, anchored to named owners.

**Allowed shape:**
- one-line what-changed summary
- one-line current-focus summary
- one-line trust-condition summary

**Allowed examples:**
- "The live setup list remains narrow; use Portfolio Snapshot and Weekly Positioning Review for actual state."
- "Trust is improved but still caution-grade because timing and evidence-quality limits remain visible in owner notes."
- "Post-earnings interpretation exists for GOOG and MSFT, but entry judgment still belongs to the weekly and trigger layers."

**Not allowed:**
- detailed name-by-name adjudication that duplicates weekly owner logic
- exact deployment-board restatement without explicit owner framing

## Surface-by-surface contract

## 1) `01. Dashboards/Executive Brief.md`

### Allowed claim shapes
- derived orientation summary
- unresolved-truth warning
- freshness warning
- fresh brief signal
- report-intelligence link

### Exact allowed sentence behavior
`Executive Brief` may say:
- what changed materially at a high level
- whether trust/freshness is degraded
- whether a new brief, packet, or scorecard exists
- where to go for the canonical weekly / portfolio / risk answer

`Executive Brief` may not say:
- the final live deployment list as independent canon
- detailed catalyst sequencing that belongs to weekly owners
- named ticker state judgments unless explicitly framed as derived and owner-subordinate

### Required wording posture
When naming a ticker or setup condition here, use one of these forms:
- "[Name] has a fresh brief / scorecard; use the owner note before changing state."
- "[Name] remains under review / conditional / unresolved in the owner layer."
- "Current dashboard trust is caution-grade because [specific limitation] remains unresolved."

### Prohibited wording posture
Do not use `Executive Brief` for:
- "deployable now" claims without explicit owner attribution
- blocker clearance language from packet freshness alone
- exact portfolio or trigger-sheet logic restatement

## 2) `01. Dashboards/This Week.md`

### Allowed claim shapes
- derived weekly orientation summary
- unresolved-truth warning
- fresh brief signal
- navigation / report link
- bounded success-condition framing

### Exact allowed sentence behavior
`This Week` may say:
- the intended outcome for the week
- which review items or fresh reports matter this week
- which unresolved evidence still blocks a clean judgment
- which owner note holds the real weekly map

`This Week` may not say:
- a second weekly deployment map
- a second catalyst canon
- name-by-name state logic beyond brief orientation wording

### Required wording posture
When using WF21/WF22-derived signals here, keep them in one of these forms:
- "This week requires review of [report/scorecard], but final posture still belongs to [owner note]."
- "A stale phrase was reconciled, but the owner note remains the source for current state."
- "Success this week means current evidence is reflected honestly, not that every name becomes actionable."

### Prohibited wording posture
Do not use `This Week` to:
- state exact entry-band or stop logic
- infer that post-earnings interpretation equals deployability
- carry unresolved catalyst dates as if this note owns timing truth

## 3) `01. Dashboards/Next Actions.md`

### Allowed claim shapes
- action-routing prompt
- unresolved-truth warning
- fresh brief signal
- report-intelligence link

### Exact allowed sentence behavior
`Next Actions` may say:
- what to read next
- what to confirm before acting
- which unresolved issue blocks a clean decision
- which owner note or report should be used before any state change

`Next Actions` may not say:
- trade-authorizing language
- independent thesis changes
- direct promotion/demotion of a name unless the owner note already made that change and the dashboard is merely routing to it

### Required wording posture
Use one of these forms:
- "Read [owner/report] before touching [name/theme]."
- "Keep [name] in review-only mode until [specific owner/evidence condition] is resolved."
- "Confirm [warning or owner-state] before closing this action."

### Prohibited wording posture
Do not use `Next Actions` to:
- convert a review task into a final decision
- restate full weekly posture analysis
- imply a blocker is cleared because a dashboard warning disappeared

## Unresolved-truth wording rules
When truth is partial, stale, conflicted, or secondary-only, the dashboard must degrade visibly.
Allowed unresolved-truth language should be blunt and specific.

### Preferred unresolved-truth forms
- primary-source capture incomplete
- owner note not yet updated
- post-earnings interpretation exists, but final state remains owner-bound
- timing confirmation still pending
- stale wording was cleaned up, but canonical judgment remains elsewhere
- evidence is constructive, not decision-clearing

### Avoid
- resolved
- fresh
- cleared
- confirmed
- ready
- deployable
unless the canonical owner already says that explicitly and the dashboard is clearly subordinate to that owner.

## Freshness rules
Freshness in dashboards means **recency of evidence access**, not automatic decision quality.

### Allowed freshness statements
- a new packet exists
- a scorecard was completed
- a weekly brief was refreshed
- a stale phrase was removed or reconciled
- validation is cleaner, but caution remains

### Not allowed
- "fresh therefore safe"
- "updated therefore resolved"
- "new report therefore promoted"

## Report-intelligence link behavior
Dashboards may improve retrieval speed, but links must preserve note ownership.

### Link targets allowed
- `05. Intelligence/Weekly Intelligence Brief.md`
- `05. Intelligence/Weekly Positioning Review.md`
- `03. Portfolio/Portfolio Snapshot.md`
- `03. Portfolio/Deployment Trigger Sheet.md`
- relevant scorecards or post-earnings notes
- event/risk owner notes where applicable

### Link behavior rules
- link outward to the owner/report when a summary sentence would otherwise overreach
- prefer "use / read / see owner" framing over inline paraphrase when nuance matters
- do not link directly to `tmp/` artifacts as if they are operator canon
- do not let a dashboard bullet be the only place where a material judgment appears

## WF21/WF22-derived signal examples that are allowed in practice
These examples show what may appear on dashboards **without becoming canon**.

### Allowed fresh-brief examples
- "A new ETN post-earnings packet exists; review it before changing industrials posture."
- "GOOG and MSFT scorecards now exist; entry judgment still belongs to the weekly and trigger layers."
- "The weekly intelligence brief was refreshed after the May 5 cluster; use it for the current synthesis."

### Allowed unresolved/freshness examples
- "ETN evidence is constructive, but primary-source capture remains incomplete."
- "A prior future-tense dashboard phrase was removed; use owner notes for the current post-event state."
- "Validation is cleaner, but NVDA timing confirmation still needs attention."

### Allowed action-routing examples
- "Read the XOM scorecard before changing any energy note or posture."
- "Use Weekly Positioning Review before treating the active list as changed."
- "Confirm the remaining owner-note cleanup for BRK.B before closing the catalyst item."

### Disallowed examples
- "ETN is now deployable because the packet was positive."
- "AMD and SMCI confirm the whole AI sleeve is clear to add."
- "The dashboard is fresh, so blockers are gone."
- "GS is promoted" when that promotion only exists in a dashboard sentence and not in the owner note.

## Conflict rule
If a dashboard summary, fresh brief signal, or WF22 freshness warning conflicts with a canonical owner note:
1. canonical owner wins
2. dashboard wording must degrade to unresolved-truth / review-first / link-out language
3. dashboard must not silently choose the cleaner interpretation

## Operator test before any future dashboard edit
A proposed dashboard sentence passes this contract only if all answers are yes:
1. Is the claim shape one of the allowed types above?
2. Does the sentence make the owner relationship obvious?
3. If evidence is partial or conflicted, does the wording degrade honestly?
4. Would the canonical owner clearly overrule this sentence if they diverged?
5. Is this routing/orientation language rather than state-adjudication language?

## Phase 2 verdict
WF23 Phase 2 should tighten later dashboard wording by making these claim-shape boundaries explicit, not by increasing summary density.
The safe gain is better visibility of fresh reports, unresolved truths, and next-step routing while keeping all real state judgment in the owner layer.
