# Retired Producer Manifest Removal

Read before removing a retired producer's stage from chain or window manifests (for example `WINDOW_MANIFESTS`), and before moving the producer script itself into a retirement archive. Complements the parent skill: the instruction-surface sweep owns text surfaces, the recreated-state paragraph owns flagged files; this file owns the manifest and consumer surfaces. Evidence base: the 2026-09-20 `market_state_refresh.py` removal from `chain_manifest.py` (memory/2026-09-20.md).

1. **Enumerate every window, alias, and reference before editing.** Retired stages repeat verbatim across windows, and an alias window deep-copies its base at import time, so repairing the base repairs the alias. Count step entries and `depends_on` references per window; a handed-over task list can miss a window and a downstream step (the 2026-09-20 list missed the sunday window and `weekly_macro_snapshot.py`). Complete when a search over the manifest returns zero references to the retired module name and its output path, and a guard test asserting the absence exists or is added (precedent: the alerts-chain stage guard, mirrored for window manifests in `test_chain_manifest_windows.py`).

2. **Classify each consumer by its real reads, not by its position in the list.** Optional-fallback consumers degrade gracefully on absence and keep their other dependencies. Required-spec consumers hard-fail: listing the retired artifact under required inputs makes the step raise on the file's required absence, so reclassify it to optional where in-file precedent exists and give fallback-consuming call sites a required-or-optional form (verified 2026-09-20: the market-intelligence event router required market-state for three windows while the fourth already listed it optional). Remediation or warning text instructing the retired command belongs to the parent skill's instruction-surface sweep. Tests that import or stub-execute the retired module are a containment problem owned by test artifact containment (the `test-artifact-containment` skill).

3. **Replace dependencies from proven reads, not adjacency.** A `depends_on` entry is an ordering guarantee. Derive each replacement from what the consumer actually loads (verified: the macro-regime producer reads credit-spread, breadth, and macro-metrics outputs, matching the documented live chain), and send a step to no dependencies only after confirming it reads no in-window producer output.

4. **Remove manifest stages before archiving the script.** Manifest validation errors on any step script missing from the scripts directory, so stage and `depends_on` removal is a prerequisite for archiving the producer; archiving first turns every window manifest red. Check archive-manifest sources against live manifests per the parent skill before recording them.

5. **Edit repeated manifest lines by counted replace-all, never positional hunks.** Identical step lines repeat across windows, so hunk context is ambiguous. Replace exact substrings under per-pattern count assertions, all-or-nothing before any write: the step line, solo `depends_on`, then leading, trailing, and middle list positions as separate patterns — a middle-of-list occurrence matches both the leading and trailing patterns (verified 2026-09-20: a leading-pattern assertion failed at 14 != 10 before any write; the corrected split was middle 4, leading 10, trailing 7). Preserve the file's line endings, assert zero residual references, and byte-compile the result. Finish with the chain validator for every window and the pivot validator as proof. A failed assertion must leave the file unwritten.
