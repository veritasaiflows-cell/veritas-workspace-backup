# Cleanup Source-Defect Verification

Use for cleanup traversal or manifest-ordering investigations when live cleanup is excluded. Inspection authority is not test-execution or source-write authority; use static findings alone if execution is not permitted.

1. **Pin the reviewed source.** Inspect scoped staged/unstaged diffs and hash the source and tests. Read the lane register as data; project active statuses and exact target-path matches rather than dumping historical blocked rows. Separate committed behavior from dirty additions with a read-only `git show HEAD:<path>` comparison. Finish with the reviewed preimages and overlap findings; absence of active lanes is not a write lease.

2. **Choose a no-disk-write reproduction when needed.** Parse the source with `ast`, compile only the named function definitions with annotations deferred, and explicitly supply their required globals. This avoids executing module imports, global initialization and the CLI entrypoint. Inspect selected functions for local imports and calls: extraction alone is not containment. Model filesystem state in memory and replace every reached stat, enumeration, content access, directory creation, move, cache loader/saver and report writer before calling those functions. Use `python -B` to suppress bytecode writes and make unmodelled content access raise. Finish with source-bound function execution whose mutations affect only the synthetic map; report it as mocked reproduction, not real-filesystem integration proof.

3. **Make traversal omissions observable.** Give every parent directory an explicitly old timestamp and a nested file a strictly newer timestamp across the eligibility cutoff. Assert newest time, complete file inventory and eligibility independently; incidental creation times or making only a nested file older can hide skipped descent. Inspect the visited-set seed against the worker's first duplicate check: pre-seeding the worker root can skip the whole subtree. Compare that call with an ancestor-only seed as a control. Finish with observed failure/control results; a passing control does not establish cycle/junction coverage or verify an applied repair.

4. **Trace evidence construction across movement.** Test file and directory candidates separately. In memory, move each source to its destination, leaving the source absent; observe digest construction, candidate-record construction and the report sink. Record changed digests, exact exception sites and report-write counts separately: an earlier digest may silently change while the later manifest raises. Recommend capturing source records and digest before mutation, but distinguish that ordering repair from durable partial-move recovery ([partial-apply recovery](partial-apply-recovery.md)), which is what a real interrupted apply needs. Finish with the demonstrated call sequence and proposed regression assertions; neither a proposed precomputation change nor successful moves alone prove a recovery report survives interruption.

5. **Close without changing the evidence under review.** Recheck source/test hashes and lane state. Report static inspection, mocked execution, unrun integration tests and unapplied proposals separately. Source repair and fixture outputs require their own exact write scope. For claims about missing historical proof, use [historical lane validation](../../veritas-workspace-audit-orchestrator/references/historical-lane-validation.md): a reproduced possible failure path is not evidence that it caused a particular loss.
